## TURN 01.01 — Audit create_new_turn, fs_ls and write_tasks

### Notes

1. create_new_turn's dry run must use the turn the operations will run in: a fresh empty turn when the active one is sealed, the active turn only when it is reused. fill_turn runs write_files before its own apply_meta, so a dry run against the wrong turn lets a failing note or task op leave file changes on disk. Fix is in src/state/turns.rs; it is not compiled or tested yet because the agent-mcp tools cannot run cargo.

+        // Dry run on a copy of the turn the operations will run in, so that note/task errors

### Handover Tasks

1. Verify and fix: fs_ls ignores its `size` parameter. FsLsParams exposes `size`, but src/fs_tools/ls.rs builds the ListSpec with `size: None`. Pass `p.size` through.

2. Verify and fix: apply_task_ops in src/state/handover_tasks.rs removes tasks with turn.tasks.remove(i) inside the loop, so several Delete ops in one write_tasks call shift later indices mid-batch. write_notes avoids this with slot-based deletion; make write_tasks behave the same.

3. Update the tests for the create_new_turn fix in src/state/turns.rs: add a regression test where a task from the turn being closed is rolled over in the same create_new_turn call, and a test where a note Edit targets a note of the closed turn and must fail without changing files on disk.
